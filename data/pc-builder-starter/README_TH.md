# ข้อมูลตั้งต้นสำหรับร้านขายและจัดสเปกคอมพิวเตอร์

อ่าน manifest.json เพื่อดู commit ต้นทางและจำนวนรายการจริง

## โครงสร้าง
- 01_raw/buildcores/: JSON ต้นฉบับรายสินค้า แยกตามหมวดของต้นทาง
- 02_catalog/: ข้อมูลพร้อมอ่าน แยก cpu, gpu, motherboard, ram, psu, cpu_cooler, case, ssd, hdd และ storage_other หากชนิดไม่ชัดเจน
- 03_schemas/: JSON Schema ต้นทาง ใช้อ่านความหมาย ชนิดข้อมูล และหน่วย
- 04_benchmarks/: สถานะการดาวน์โหลด benchmark และคำอธิบาย
- 05_manual_data/: แม่แบบ CSV ว่างสำหรับ CPU support/BIOS ราคา สต็อก และ benchmark จริง
- 06_docs/: จำนวนสินค้า checksum และรายงานความครบของทุกฟิลด์
- 07_scripts/: ตัวอย่าง Python พร้อมคอมเมนต์ภาษาไทย
- licenses/: README ใบอนุญาต และ NOTICE ต้นฉบับ

## เริ่มใช้
อ่าน 02_catalog/<หมวด>/parts.json ด้วย Python json หรือใช้ CSV กับ pandas/database
opendb_id เป็นรหัสเชื่อมข้อมูล ห้ามใช้ชื่อสินค้าเป็น primary key
SSD/HDD แยกจาก storage_type ที่ระบุชัดเจนเท่านั้น ไม่เดาจากชื่อ
รายงาน field_coverage.csv นับค่าที่ไม่ว่าง ไม่ได้ยืนยันความถูกต้อง; ค่า 0 ยังถูกนับว่ามีค่า
CSV เป็น flattened view; หากต้องการชนิดข้อมูลที่แม่นยำให้ใช้ JSON และ schema

## Compatibility
ตรวจทั้งชิ้นส่วนที่เลือกทั้งหมดและข้อจำกัดระดับทั้งเครื่อง
socket ตรงกันยังไม่ยืนยัน CPU support/BIOS
ตรวจ DDR, ความจุ/จำนวนแถว, ขนาด GPU/ซิงก์, ขั้วต่อ PSU และช่อง SSD
ต้องเพิ่มข้อมูลระยะเมื่อใส่หม้อน้ำ การแชร์เลน/พอร์ต และ revision จากคู่มือ
หากข้อมูลหายหรือค่า 0 ไม่ชัดเจน ให้ผล unknown ไม่ใช่ compatible
ข้อมูลนี้ยังไม่ใช่ระบบ compatibility ที่ผ่านการตรวจครบทุกสินค้า

## Machine learning
catalog เป็น features ไม่ใช่ผลทดสอบหรือ label ประสิทธิภาพ
ต้องเพิ่ม benchmark จริงก่อนฝึก performance prediction
คะแนน Blender ใช้อธิบายงานเรนเดอร์ ไม่ใช่ FPS เกม
แบ่ง train/test ตามรุ่นหรือช่วงเวลาเพื่อลดการรั่วไหลของข้อมูล
